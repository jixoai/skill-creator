# Skill Creator 中文领域语言

本文件是领域词汇表，不是 UI 字符串翻译文件。词汇分成「用户一手术语」与「本轮架构决策」，不得把后者伪装成用户原话。

## 1. 用户一手术语

以下内容直接来自 2026-07-14 至 2026-07-22 的需求：

| 用户原词                           | 原始语义                                          | 保留方式                                                                                        |
| ---------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `skills 管理器`                    | 基于 ccski 管理技能                               | 产品类别使用「技能管理器（Skills Manager）」                                                    |
| `cli+gui(webui+opentray)`          | CLI 与 tray WebUI 共用本地应用架构                | 架构图保持 CLI / WebUI / OpenTray 三个名词                                                      |
| `workspace`                        | 技能管理路由的作用域，并支持导入                  | 保留英文专名 Workspace，中文写「工作区」                                                        |
| `/workspace/~/`                    | 技能管理器的一个明确路由                          | `~` 保留为特殊 Workspace ID                                                                     |
| `GlobalWorkspace` / home           | 包含各种 Agent skills 的特殊 Workspace            | 统一命名为 Global Workspace；它不是一个单独 root 目录                                           |
| `provider`                         | 一个 Workspace 下可有多个 Agent skills 根目录     | 保留 Provider；所有 skills 操作使用 Workspace.Provider 双层作用域                               |
| `下载到某个 Workspace.provider`    | Repository 安装的本地目的地                       | 使用 Workspace Provider Target；Repository 支持多选目的地                                       |
| `创造、编辑 技能`                  | 同一路由中的创建与编辑能力                        | 统一命名为 Creator，并明确 create + edit                                                        |
| `/creator`                         | 技能创作路由                                      | 路由和一级导航名固定为 Creator                                                                  |
| `/repository/`                     | 远程仓库技能预览与安装                            | 路由和一级导航名固定为 Repository                                                               |
| `二者是有机互联的`                 | Workspace、Creator、Repository 共享人的任务上下文 | 通过显式 Workspace 目标和跨路由导航连接，不合并领域边界                                         |
| `以人为本`                         | 从小白到专业工程师都应可操作                      | UI 决策优先直觉、密度、反馈和可恢复性                                                           |
| `大胆创新`                         | 可补全、重构、删除或增加模块                      | 不能突破安全边界，也不能把演示状态写成真实能力                                                  |
| `appMode:true`                     | 使用正常应用窗口而不是 keep-on-top tray panel     | 统一命名为 App Mode；窗口生命周期交给系统管理                                                   |
| `最小推荐尺寸`                     | 路由只补足窗口不足的宽高，不缩小更大的当前窗口    | 统一命名为 Minimum Recommended Size；只在路由变化时向 native bridge 请求补足                    |
| `skill-creator openinbrowser`      | 用户显式要求在系统浏览器访问当前 WebUI            | 统一命名为 Explicit Browser Open；`start` 与 `open` 只能提示，不能隐式执行                      |
| `appIcon` 必须跟随操作系统平台标准 | 应用身份图标不能复用 tray icon 的宽松协议         | macOS 使用 ICNS、Windows 使用 ICO、Linux 使用标准尺寸 PNG/SVG；生成工具是可选辅助，不是协议本身 |
| 默认的变体名是 `default`           | App icon 未填写 `variant` 时的规范名称            | light 资产可用 `["default", "light"]` 同时作为启动默认值和显式 light 状态                       |
| 垃圾篓 `empty/files`               | 图标变体是语义状态，不只表示主题                  | Core 只校验和选择名称；具体状态与 IPC 由应用定义                                                |
| 破坏性更新与 `safeParse` 空值      | 不兼容旧持久态不迁移，整体按空值处理              | 统一命名为 Incompatible Persisted State；只保留当前 schema，下一次正常 mutation 才写回当前状态  |
| 配置文件、数据库结构、网络返回     | 一切跨信任边界的数据都先 runtime 收窄             | 统一命名为 External Input Boundary；读取可按领域投影为空，命令与安全输入必须明确拒绝            |

## 2. 本轮架构决策

以下命名由 2026-07-14 至 2026-07-21 的代码审计与重构收敛，不是用户逐字指定：

```text
Workspace
|-- Global Workspace (~) ------ catalog-resolved Agent global roots
`-- Imported Workspace (ws_*) - canonical registered directory
    `-- Provider -------------- Agent skills root under that Workspace

Workspace Registry ------------ one daemon-owned persisted scope authority

Skill (sk_*) ------------------ workspace-scoped local skill
Repository Scan Session ------- pinned clone at one commit
Remote Skill (rsk_*) ---------- skill inside that session
Skill Document Revision ------- sha256 of current SKILL.md
Canonical Skill (search) ------ realpath 去重后的索引身份主键
Installation (search) --------- {path, workspaceId, providerId} 入口观察三元组
Skill Content Hash ------------ 实际被索引 SKILL.md 字节的 sha256
Search Payload Digest --------- 信封 {index, stats} 的 sha256（写入算/加载验）
```

| 决策词                       | 定义依据                                                                                                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Global Workspace             | `~` 由 contract 保留；按 Agent Provider catalog 聚合全局 skills roots                                                                                                                              |
| Imported Workspace           | daemon 对显式导入目录执行 canonicalize 后注册并分配 `ws_*`                                                                                                                                         |
| Provider                     | catalog 中的 Agent；在 Global Workspace 解析其全局 root，在 Imported Workspace 派生其 project root                                                                                                 |
| Workspace Provider Target    | `{ workspaceId, providerId }`；唯一可传递的 skills 作用域与 Repository 多选安装目标                                                                                                                |
| Workspace Registry           | daemon 唯一持有的持久作用域真相；动态计数不属于其状态                                                                                                                                              |
| Incompatible Persisted State | 无法通过当前 Zod schema 的可解析旧持久态；加载时整体视为空值，不迁移、不写回，下一次正常 mutation 才提交当前状态                                                                                   |
| External Input Boundary      | 文件、未来数据库记录、网络/第三方返回先解码为 `unknown`，只经当前 Zod schema 进入领域；不会放宽旧 schema                                                                                           |
| Empty Projection             | 可恢复读取的不兼容完整快照按当前领域的空值表示；集合中的不兼容条目直接丢弃，不触发加载期写回                                                                                                       |
| Typed Rejection              | 命令、鉴权、路径、mutation 或不能安全表达为空的外部结果必须产生可处理错误；不把安全失败伪装成空状态                                                                                                |
| Opaque ID                    | API 身份不暴露路径拼接能力；server 负责解析 ID                                                                                                                                                     |
| Pinned Commit                | Repository scan clone 后以 `git rev-parse HEAD` 固定内容身份                                                                                                                                       |
| Repository Scan Session      | `repo_*` 绑定 commit、临时 clone 与 Remote Skill 映射                                                                                                                                              |
| Revision-safe Edit           | update/delete 必须提交当前 `SKILL.md` 的 SHA-256 revision                                                                                                                                          |
| Tray Workbench               | OpenTray ext-webview 承载的本地 WebUI 窗口                                                                                                                                                         |
| App Mode                     | OpenTray 正常应用窗口模式；进入系统任务栏/Dock/应用切换器，焦点与关闭由系统管理                                                                                                                    |
| App Icon                     | 进程级应用身份资产；Skill Creator 由 `@opentray/vite-plugin` 预构建当前平台标准文件，不使用 tray template 图标                                                                                     |
| App Icon Variant             | App identity 的语义状态名；本项目声明 `default/light/dark`，不把主题监听耦合到 ext-webview                                                                                                         |
| App Icon Representation      | 预览/Linux PNG 使用 72 DPI；macOS ICNS 用独立 @1x/@2x tag 保持正确 pixel/point 映射                                                                                                                |
| Headless                     | daemon 存活但 tray capability 未挂载；不是 daemon 断线                                                                                                                                             |
| Development Launch Vector    | Dock 冷启动使用绝对 Node、真实 `node_modules/vite/bin/vite.js` 与 webui cwd；不经过 pnpm、package script 或 `.bin` shim                                                                            |
| Development Takeover         | `pnpm dev` 先停止正式 daemon，并等待 IPC endpoint 与 PID 同时释放后接管同一 OpenTray app identity                                                                                                  |
| Production Launch Vector     | Dock 冷启动使用绝对 Node + `dist/cli.js start`；CLI 统一启动、open/focus 与失联 tray 恢复                                                                                                          |
| Linked Runtime Staging       | 本地 link OpenTray 时，在 `dev` 与生产 `start` 前构建并暂存同一源码图的 facade、broker/carrier 与 native extension                                                                                 |
| Dock Cold Relaunch           | tray/daemon 退出后从稳定 `.app` 执行最近的启动向量，恢复 Vite、daemon、WebView 完整进程树                                                                                                          |
| Request Generation Gate      | 一个请求代次与 connection owner generation 的提交能力组合；`isLatest` 只清理 loading，`isCurrent` 才能提交状态或继续 RPC                                                                           |
| Skill Search Index           | 本地 BM25+ 技能检索域：Canonical 去重 + 文件集正文（SKILL.md + 额外 md，排除目录可配）+ 冻结 rerank；信封 v3（+searchConfigDigest/文件集 stat）+ watcher 事件驱动新鲜度；duplicates 无查询重复组面 |
| SkillTokenizer               | 冻结规则检索分词器（NFKC + Segmenter + 连续单字滑窗 bigram + Latin 切分）；query/doc 同管线且版本化                                                                                                |
| Canonical Skill (search)     | realpath 归并的索引真相；installations 才是入口观察，不作身份                                                                                                                                      |
| Skill Content Hash           | 仅 SKILL.md 字节级 sha256（内容分组/dup 折叠），不是目录指纹                                                                                                                                       |

## 3. Canonical Glossary

| Skill Creator                | Skill Creator / 技能创作器 | 产品名；同时包含管理、创作和仓库安装三类人的任务                                                                       |
| Skill                        | 技能                       | 由一个目录及其 `SKILL.md` 表达的 Agent 能力单元                                                                        |

| Request Generation Gate      | 请求代次门                 | 在一个 owner 内 latest-request-wins；`isLatest` 只允许 loading cleanup，`isCurrent` 才允许状态、错误或后续 RPC         |

## 4. 禁止混用

```text
Import Workspace  != Install Skill
Enable/Disable    != Install/Delete
Workspace ID      != filesystem path
Skill ID          != skill name / directory name
Ref               != Pinned Commit
Canonical Skill   != 入口路径（installations 是观察，不是身份）
Skill Content Hash != 目录指纹（仅 SKILL.md 字节级）
Payload Digest    != 认证（无密钥；只防未重算摘要的篡改）
Revision          != package version / Git commit
Headless          != Disconnected
Remove Workspace  != Delete Directory
Request Generation != request cancellation
Repository        != Marketplace
Scan              != Search
App Mode          != Keep-on-top tray panel
Empty Projection != successful mutation
Typed Rejection != Empty Projection
```

| 必须使用                     | 禁止替代                                | 原因                                                               |
| ---------------------------- | --------------------------------------- | ------------------------------------------------------------------ |
| Workspace                    | Project、Repo、Folder（当表达作用域时） | Workspace 是协议作用域；folder 只表达文件系统对象                  |
| Incompatible Persisted State | Legacy migration                        | 当前 schema 外的可读快照按空值加载；不读取旧字段，也不引入迁移脚本 |
| Empty Projection             | Typed Rejection                         | 可恢复的读取可为空；命令、安全输入和不可安全降级的结果必须显式失败 |
| Global Workspace             | Home Workspace、Root Workspace          | `~` 聚合 catalog 中多个 Provider roots，不等于一个 root 目录       |
| Workspace Provider Target    | Workspace ID                            | Provider 是安全作用域的一部分，不能只传 Workspace                  |
| Imported Workspace           | Local Repo                              | 导入目标只要求目录，不要求它本身是 Git 仓库                        |
| Import Workspace             | Install Workspace                       | import 只注册 canonical directory，不执行内容安装                  |
| Creator                      | Editor（当指整个路由时）                | `/creator` 同时承担 create 与 edit/delete                          |
| Repository                   | Marketplace、Gallery                    | 当前来源是明确 Git source，不存在中心化目录服务语义                |
| Repository Scan              | Repository Search                       | 当前动作 clone 并遍历固定快照，不是远端全文检索                    |
| Pinned Commit                | Branch、Latest                          | ref 是输入，commit 才是 preview/install 的内容身份                 |
| Revision                     | Version                                 | revision 是单个文件内容 hash，不是发布版本                         |
| Enable/Disable               | Install/Uninstall                       | toggle 改变现有技能状态；install 改变目标目录内容                  |
| Remove Workspace             | Delete Workspace                        | remove 只删除 registry entry，不应暗示删除用户目录                 |
| Headless                     | Offline、Disconnected                   | headless 时 daemon/HTTP/IPC 仍可能正常工作                         |
| Opaque ID                    | Path                                    | ID 只授予已注册对象能力，不能作为路径输入使用                      |
| Request Generation Gate      | AbortController / 普通重试              | 它是结果提交权限，不承诺终止底层 RPC 或重新执行请求                |

# 2026-09-06 技能管家目标词汇（尚未实现）

- 技能管家（Skill Steward）：为本地 skills 提供分析、禁用、优化、拆分、合并的专属 Agent 工作流。
- 运行快照（Context Snapshot）：一次读取所得的技能字节、revision、配套资源和 evidence；不会因执行中编辑而自动更新。
- 校验（Validation）：检查方案是否合法、引用是否完整和 revision 是否有效，不产生授权。
- 用户批准（Human Approval）：人类对确定 patch 的一次授权；DSH permission 不能代替 Manager approval。
- 恢复待处理（Recovery Required）：多文件补偿无法完成的可见状态；保留 journal 与备份并封锁目标后续写入。
- Web 组合（DSH Web Composition）：复用官方 Agent settings/session/chat/permission 插件，与 Manager views 共用产品 Shell；不是 ACP 对话转发。

# 2026-09-21 skill-wiki 与检索内核词汇（jixoai-search-core）

- 经验 Wiki（skill-wiki）：agent 持久经验的 wiki 层领域库（WikiSkill 论文 arXiv:2608.27454）；patterns 唯一真相、index/logs/skill-impact 为投影或审计；碎片认知追加（P1 已并入）是其摄取输入。
- 泛化（Generalization）：LLM Maintainer 把 workspace 认知蒸馏进 global（新建页面或经 patch 吸收）的过程；workspace 原文永不删除，`promotedFrom` 是贡献溯源足迹而非机械搬运。
- 双级作用域（Dual Scope）：global `~` 与按 workspace 的单词串 slug（npm-scope 式）；registry 内部仍用 ws_ digest id，wiki 侧使用人类可读名（先注册者保留裸名）。
- 检索内核（@jixoai/search）：org 级通用索引/搜索包——后端只做召回与持久化（sqlite FTS5 默认/tantivy 单进程可选），BM25 变体打分冻结在 JS 共享层，公共 API 零引擎概念泄漏。
- 相似警告（Similarity Warning）：碎片追加后的自动近亲检索提示（相对分阈值冻结）；警告不是错误，`edit` 吸收 + `remove` 删重构成纠偏闭环。
